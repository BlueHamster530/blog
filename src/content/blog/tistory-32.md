안녕하세요!

자바스크립트로 웹 애플리케이션을 개발할 때, 우리는 수많은 코드 파일과 서버 통신을 다루게 됩니다. 이때 두 가지 개념이 개발의 품질과 효율성을 크게 좌우합니다.

바로 **모듈(Module)** 시스템과 **Axios** 같은 HTTP 통신 라이브러리입니다.

왜 우리는 코드를 import/export로 분리해야 할까요? 그리고 브라우저에 내장된 Fetch API가 있는데도 왜 굳이 Axios라는 라이브러리를 추가로 설치해서 사용할까요?

오늘은 이 두 가지 핵심 주제에 대해 그 이유와 장점을 명확하게 정리해 보겠습니다.

---

### 1. 자바스크립트에서 모듈(Module)을 사용하는 이유

자바스크립트에서 모듈을 사용하는 가장 핵심적인 이유는 **코드의 분리와 재사용성을 높이고, 전역 스코프(Global Scope)의 오염을 막기 위해서**입니다.

초기 자바스크립트는 <script> 태그를 사용하여 여러 파일을 불러왔습니다. 이 방식은 모든 파일이 **하나의 전역 스코프**를 공유하게 만들어 다음과 같은 심각한 문제들을 야기했습니다.

- **이름 충돌 (Naming Collision):** 다른 파일에서 동일한 이름의 변수나 함수를 선언하면, 나중에 로드된 파일의 코드가 이전에 로드된 코드를 덮어쓰는 문제가 발생합니다.
- **의존성 관리의 어려움:** 파일 간의 의존 관계가 명확하지 않아, <script> 태그의 로드 순서가 매우 중요해지고 관리가 어려워집니다.
- **유지보수의 어려움:** 모든 코드가 전역에 존재하므로, 코드의 특정 부분을 수정할 때 다른 부분에 어떤 영향을 미칠지(Side Effect) 예측하기 어렵습니다.

ES6(ES2015)에서 표준으로 도입된 **모듈 시스템(import / export)**은 이러한 문제들을 깔끔하게 해결합니다.

#### 모듈 사용의 핵심 이점

1. **독립적인 스코프 (모듈 스코프)** 모든 모듈 파일은 자신만의 **독립적인 스코프**를 가집니다. 모듈 내부에서 선언된 변수, 함수, 클래스는 기본적으로 해당 모듈 내부에서만 사용할 수 있습니다. 이로 인해 전역 스코프가 오염되지 않으며, 이름 충돌 문제가 원천적으로 방지됩니다.
2. **명시적인 의존성 관리**
   - **export** 키워드를 사용해 외부에서 사용할 수 있도록 명시적으로 **공개할 항목**을 지정합니다.
   - **import** 키워드를 사용해 다른 모듈에서 공개한 항목을 명시적으로 **가져와 사용**합니다. 이 과정을 통해 코드 간의 의존 관계가 파일 상단에 명확하게 드러나, 코드 분석과 관리가 쉬워집니다.
3. **재사용성 및 유지보수성 향상** 기능별로 코드를 작은 모듈 파일로 분리(모듈화)할 수 있습니다. 특정 기능이 필요한 곳이면 어디든 해당 모듈을 import 하여 재사용할 수 있습니다. 기능 수정이 필요할 때 해당 모듈만 수정하면 되므로 유지보수성이 크게 향상됩니다.

### 2. Fetch API 대비 Axios 라이브러리의 장점

서버와 데이터를 주고받기 위해 우리는 Fetch API나 Axios 같은 HTTP 클라이언트를 사용합니다. Fetch API는 브라우저에 내장된 강력한 비동기 통신 API입니다.

Axios는 Fetch와 동일한 역할을 하지만, Fetch에 비해 **개발자를 편하게 해주는 몇 가지 유용한 기능**을 추가로 제공하여 실무에서 매우 널리 사용됩니다.

Axios를 사용했을 때의 주요 이점은 다음과 같습니다.

#### 1. JSON 데이터 자동 변환

- **Fetch:** POST 요청 시 body에 데이터를 담아 보낼 때 JSON.stringify()를 사용해 수동으로 문자열로 변환해야 합니다. 응답을 받을 때도 response.json() 메서드를 호출해야 실제 JSON 데이터를 얻을 수 있습니다.
- **Axios:** 요청 데이터를 **자동으로 JSON 문자열로 변환**해 줍니다. 또한, 응답 데이터도 **자동으로 JSON 객체로 파싱**하여 response.data에 담아줍니다. 이로 인해 불필요한 변환 코드가 줄어듭니다.

#### 2. 간편한 에러 핸들링

- **Fetch:** 404 Not Found나 500 Internal Server Error 같은 HTTP 에러 상태 코드를 받아도, fetch() 프로미스는 에러로 간주하지 않고 정상적으로 resolve합니다. 개발자가 response.ok 속성(200-299 상태일 때 true)을 직접 확인하고 에러를 throw 해야 .catch() 문에서 처리할 수 있습니다.
- **Axios:** **2xx 범위를 벗어나는 모든 HTTP 상태 코드를 에러로 간주**하여 자동으로 프로미스를 reject합니다. 따라서 .catch() 블록에서 HTTP 에러를 일관되게 처리할 수 있습니다.

#### 3. 요청/응답 인터셉터 (Interceptors)

Axios의 가장 강력하고 유용한 기능 중 하나입니다.

- **요청 인터셉터 (Request Interceptor):** 모든 요청이 서버로 전송되기 전에 가로채서 특정 작업을 수행할 수 있습니다. (예: 모든 요청 헤더에 인증 토큰(JWT) 자동으로 추가하기)
- **응답 인터셉터 (Response Interceptor):** 서버로부터 응답을 받은 후, .then()이나 .catch()로 전달되기 전에 가로채서 공통 작업을 처리할 수 있습니다. (예: 특정 에러 코드(401 Unauthorized)일 경우 자동으로 로그인 페이지로 리다이렉트)

#### 4. 구형 브라우저 호환성

- **Fetch:** 최신 API이므로 IE(Internet Explorer) 같은 일부 구형 브라우저에서는 지원되지 않습니다. (폴리필(polyfill) 사용 시 해결 가능)
- **Axios:** 내부적으로 XMLHttpRequest(XHR) 객체를 기반으로 동작하므로 대부분의 구형 브라우저에서도 별도 설정 없이 호환됩니다. (최근에는 이 장점이 크게 부각되지는 않습니다.)

---

### 마치며

**모듈 시스템**은 자바스크립트 코드의 **관리(유지보수)**를 위한 필수적인 기반이며, **Axios**는 서버와의 **통신(데이터 교환)**을 편리하게 해주는 훌륭한 도구입니다.

두 가지 모두 모던 웹 개발 환경에서 코드의 품질과 개발 효율성을 높이는 데 크게 기여하므로, 이 둘의 장점을 명확히 이해하고 활용하는 것이 중요합니다.
