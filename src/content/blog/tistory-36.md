안녕하세요!

우리가 매일 사용하는 VS Code(Visual Studio Code)는 마이크로소프트가 관리하는 세계에서 가장 유명한 오픈소스 프로젝트 중 하나입니다.

'오픈소스'라는 말은 누구나 코드를 보고, 사용하고, 심지어 **개선에 참여(기여)**할 수 있다는 뜻입니다. 하지만 막상 기여하려고 하면, 이 거대한 프로젝트에 내가 작성한 코드를 어떻게 반영해야 할지 막막하게 느껴집니다.

오늘은 이렇게 전 세계 개발자들이 협업하는 대규모 오픈소스 프로젝트가 어떤 방식으로 운영되는지, **'Fork & Pull Request'** 모델을 중심으로 실제 기여 절차 7단계를 microsoft/vscode 예시와 함께 자세히 알아보겠습니다.

---

### 오픈소스 협업의 표준: Fork & Pull Request 모델

microsoft/vscode 원본 저장소는 아무나 코드를 수정(Push)할 수 없습니다. 따라서 기여자는 **'원본을 내 저장소로 복사(Fork)'**한 뒤, 내 저장소에서 자유롭게 수정하고, **'수정한 내용을 원본에 반영해달라고 요청(Pull Request)'**하는 방식을 사용합니다.

이것이 바로 'Fork & Pull Request' 모델입니다.

#### 협업 절차 (기여자의 관점)

**1단계: 기여할 내용 찾기 (Issue 확인)**

무작정 코드를 수정하기 전에, 먼저 **소통**이 필요합니다.

microsoft/vscode 저장소의 **'Issues'** 탭을 확인합니다. 여기서 다른 사람들이 제보한 버그나 기능 요청을 살펴봅니다. 처음이라면 간단한 오타 수정(typo)이나 문서 수정처럼 **'good first issue'** 라벨이 붙은 것을 선택하는 것이 좋습니다.

만약 자신이 새로운 버그를 찾았다면, 먼저 기존에 동일한 이슈가 없는지 검색한 후 새로운 이슈를 등록하여 프로젝트 관리자(Maintainer)들과 논의를 시작합니다.

**2단계: Fork (포크)**

기여할 이슈를 정했다면, 이제 코드를 수정할 준비를 합니다. 원본 저장소는 내가 직접 수정(Push)할 권한이 없으므로, GitHub 웹사이트에서 **'Fork'** 버튼을 누릅니다.

이 작업은 microsoft/vscode 원본 저장소를 내 개인 GitHub 계정(예: my-username/vscode)으로 **그대로 복사**해오는 과정입니다. 이제 이 복사본은 **내 소유**이므로 자유롭게 수정할 수 있습니다.

**3단계: Clone (클론) 및 Branch (브랜치) 생성**

내 컴퓨터(로컬)에서 작업하기 위해, **내가 Fork한 저장소**를 git clone 명령어로 내려받습니다.

```
# 주의: 원본(microsoft)이 아닌 내 저장소(my-username)를 클론합니다.
git clone https://github.com/my-username/vscode.git
cd vscode
```

그다음, **내 작업 전용 브랜치**를 새로 만듭니다. 이는 원본의 main 브랜치와 내 작업 내용을 **격리**하여 깔끔하게 관리하기 위함이며, 오픈소스 협업의 필수적인 습관입니다.

```
# 'fix-login-bug'라는 이름의 새 브랜치를 만들고 그 브랜치로 이동합니다.
git checkout -b fix-login-bug
```

**4단계: 코드 수정 및 Commit (커밋)**

이제 VS Code로 실제 코드를 수정합니다. (예: 1단계에서 찾은 로그인 관련 버그 수정)

수정이 완료되면, 변경 사항을 '스테이징(Staging)'하고 '커밋(Commit)'하여 로컬 저장소에 기록을 남깁니다.

```
git add .
# (#12345는 1단계에서 확인한 이슈 번호이며, 연결해두면 관리가 편함)
git commit -m "Fix: 로그인 시 발생하는 500 에러 수정 (#12345)"
```

**5단계: Push (푸시)**

로컬에 커밋한 내용을 **내 GitHub Fork 저장소**로 밀어 올립니다(push).

```
# 'origin'은 기본적으로 내가 클론한 'my-username/vscode'를 가리킵니다.
git push origin fix-login-bug
```

**6단계: Pull Request (PR) 생성**

이제 **협업의 꽃**인 Pull Request를 생성할 차례입니다.

my-username/vscode GitHub 저장소 페이지에 접속하면, 방금 푸시한 fix-login-bug 브랜치를 기반으로 **"Pull Request"**를 생성하라는 버튼이 보입니다.

이 버튼을 클릭하면, **'내가 수정한 내용(Head: my-username/vscode의 fix-login-bug 브랜치)을 원본 저장소(Base: microsoft/vscode의 main 브랜치)에 합쳐주세요'**라는 **공식 요청서(PR)**가 작성됩니다.

이때, 내가 무엇을 왜 수정했는지(1단계의 이슈 내용 요약) 상세히 기술하는 것이 매우 중요합니다.

**7단계: 코드 리뷰 (Code Review) 및 병합 (Merge)**

이제 공은 VS Code의 **프로젝트 관리자(Maintainer)**들에게 넘어갑니다.

이들은 내 PR을 확인하고, 내 코드를 리뷰합니다. "이 부분은 수정이 필요합니다", "테스트 코드를 추가해주세요" 같은 피드백을 PR에 댓글로 남길 수 있습니다.

나는 피드백에 따라 코드를 추가로 수정하고 다시 커밋/푸시합니다. (PR은 자동으로 업데이트됩니다.)

모든 리뷰가 통과되고 자동화된 테스트(CI)도 통과하면, 마침내 관리자가 **'Merge'** 버튼을 누릅니다.

---

### 마치며

'Merge'가 되는 순간, 내가 작성한 코드가 드디어 microsoft/vscode 원본 프로젝트에 공식적으로 반영되며 전 세계 수백만 명의 사용자가 사용하는 코드의 일부가 됩니다.

이것이 바로 Git과 GitHub를 통한 오픈 소스 협업의 핵심 과정입니다.

비록 VS Code는 매우 거대한 예시였지만, 이 **'Fork & Pull Request'** 모델은 크고 작은 대부분의 오픈소스 프로젝트에서 사용하는 표준 방식이니 꼭 익혀두시길 바랍니다.
