안녕하세요!

개발 공부를 하거나, 기술 면접을 준비하다 보면 꼭 마주치는 단골 질문들이 있습니다. 그중에서도 개발자라면 반드시 구분해야 할 두 쌍의 개념, 바로 **프로세스와 스레드**, 그리고 **프레임워크와 라이브러리**입니다.

이름은 비슷해 보이지만 역할과 핵심 개념은 완전히 다른데요.

오늘은 이 헷갈리는 네 가지 개념의 차이점을 확실하게 파악하고, 왜 이것을 구분하는 것이 중요한지 알아보겠습니다!

## 1. 프로세스 (Process) vs 스레드 (Thread)

"프로그램 실행"이라는 큰 그림 안에서 움직이는 두 가지 단위입니다.

- **프로세스 (Process): "실행 중인 프로그램"**
  - 우리가 흔히 아는 exe 파일이나 애플리케이션을 **더블 클릭해서 실행하는 순간!**
  - 운영체제(OS)는 이 프로그램을 위해 메모리 공간을 **'독립적으로'** 할당해 줍니다. 이 독립된 메모리 공간에서 실행되는 프로그램 인스턴스를 바로 **프로세스**라고 합니다.
  - **핵심:** 각 프로세스는 자신만의 자원(메모리, 파일)을 가지며, 다른 프로세스의 자원에 접근할 수 없습니다.
- **스레드 (Thread): "프로세스 내의 작업 흐름"**
  - 프로세스가 '실행'이라는 큰 단위라면, 스레드는 그 안에서 **'실제 작업'**을 수행하는 더 작은 단위입니다.
  - 하나의 프로세스는 하나 이상의 스레드를 가질 수 있습니다. (멀티스레딩)
  - **핵심:** 스레드들은 프로세스의 자원(메모리 중 Code, Data, Heap 영역)을 **'공유'**합니다. 하지만 각자의 작업 기록을 위한 **Stack** 영역은 따로 가집니다.

### 적당한 비유: 레스토랑

- **프로세스:** 하나의 **레스토랑** (독립된 건물, 주방, 재료 창고)
- **스레드:** 레스토랑 주방에서 일하는 **셰프들**

셰프(스레드)들은 주방과 재료 창고(메모리)를 공유하면서 각자의 요리(작업)를 동시에 진행할 수 있습니다. 스레드가 많으면(멀티스레딩) 동시에 여러 요리를 할 수 있어 효율적이죠.

### 정리 표

|  |  |  |
| --- | --- | --- |
| **구분** | **프로세스 (Process)** | **스레드 (Thread)** |
|  |  |  |
| --- | --- | --- |
| **정의** | 실행 중인 프로그램 (자원 소유 단위) | 프로세스 내의 작업 흐름 (실행 단위) |
| **메모리** | **독립된** 메모리 공간 할당 | 프로세스의 메모리 **공유** (Stack 제외) |
| **자원 공유** | IPC 등 별도 통신 필요 | 쉬움 (단, **동기화** 문제 발생 가능!) |
| **생성 속도** | 느리고 무거움 (자원 할당 필요) | 빠르고 가벼움 |

## 2. 프레임워크 (Framework) vs 라이브러리 (Library)

개발의 효율성을 높여주는 '도구'라는 점은 같지만, **'제어권(Control)'**이 누구에게 있느냐가 결정적인 차이입니다.

- **라이브러리 (Library): "내가 호출하는 도구 모음"**
  - 라이브러리는 **내가 필요할 때** 가져다 쓰는 함수나 기능의 집합입니다.
  - 애플리케이션 코드의 전체 흐름은 **'개발자(나)'**가 주도합니다.
  - **예시:** jQuery, Lodash, axios
  - **비유:** **공구함.** 집을 짓다가 망치가 필요하면 내가 공구함(라이브러리)에서 망치를 꺼내 씁니다. 제어권은 '나'에게 있습니다.
- **프레임워크 (Framework): "나를 호출하는 뼈대"**
  - 프레임워크는 애플리케이션의 **전체적인 구조와 흐름(뼈대)**을 제공합니다.
  - **'프레임워크'**가 정해진 규칙에 따라 코드를 실행하다가, 특정 부분이 필요할 때 **'내가 작성한 코드'**를 호출합니다.
  - 이것을 **"제어의 역전 (Inversion of Control, IoC)"**이라고 부릅니다.
  - **예시:** Express, Spring, Angular, Vue.js
  - **비유:** **조립식 주택 키트.** 집의 뼈대(프레임워크)는 이미 정해져 있고, 나는 그 뼈대가 요구하는 위치에 벽지를 바르거나(내 코드 작성) 가구를 배치합니다. 제어권은 '프레임워크'에게 있습니다.

### 정리 표

|  |  |  |
| --- | --- | --- |
| **구분** | **라이브러리 (Library)** | **프레임워크 (Framework)** |
|  |  |  |
| --- | --- | --- |
| **정의** | 개발자가 가져다 쓰는 도구 모음 | 개발자가 코드를 채워 넣는 뼈대 |
| **제어권** | **개발자 (내 코드)** | **프레임워크 (제어의 역전, IoC)** |
| **흐름** | 내가 라이브러리를 호출 | 프레임워크가 내 코드를 호출 |
| **비유** | 공구함 🧰 | 조립식 주택 키트 🏠 |

## 마치며

오늘은 개발자라면 꼭 알아야 할 CS 기본 개념들을 정리해 봤습니다.

- **프로세스(공장) vs 스레드(작업자)**
- **라이브러리(공구함) vs 프레임워크(뼈대)**

이 개념들을 명확히 이해하고 있으면, 멀티스레드 환경의 동기화 문제를 해결하거나 새로운 기술 스택을 선택할 때 훨씬 더 깊이 있는 접근이 가능해질 것입니다.

탄탄한 기본기가 성장의 가장 큰 밑거름이 됩니다.
