안녕하세요.

Node.js를 위한 웹 프레임워크인 Express를 공부하다 보면, 가장 많이 듣게 되는 단어가 바로 미들웨어(Middleware)입니다.

실제로 Express 공식 문서에서는 Express는 자체적인 기능은 최소한으로 갖추고, 수많은 미들웨어 함수들을 통해 구성된 프레임워크라고 정의하고 있습니다.

그만큼 미들웨어는 Express의 동작 원리를 이해하는 데 있어 가장 핵심적인 개념입니다. 오늘은 이 미들웨어가 도대체 무엇이며, 어떤 역할을 하는지 쉽게 알아보겠습니다.

### 1. 미들웨어란?

미들웨어(Middleware)는 이름 그대로 중간(Middle)에 위치하는 소프트웨어(Ware)입니다.

웹 서버의 관점에서 보면, 클라이언트(브라우저)가 **보낸 요청(Request)**이 서버에 도달하여, 최종적으로 **응답(Response)**을 내보내기까지의 과정 **중간**에 위치하여 특정 기능을 수행하는 함수들을 말합니다.

쉽게 비유하자면 **공장의 컨베이어 벨트**와 같습니다.

1. 원재료(요청)가 컨베이어 벨트에 올려집니다.
2. 첫 번째 작업자(미들웨어 1)가 재료를 씻습니다.
3. 두 번째 작업자(미들웨어 2)가 도색을 합니다.
4. 마지막 작업자(라우터)가 완성품(응답)을 포장하여 내보냅니다.

이 과정 중간중간에 서 있는 작업자들이 바로 미들웨어입니다.

### 2. 미들웨어의 구조와 역할

Express에서 미들웨어 함수는 기본적으로 세 가지 인자를 받습니다.

**req (Request):** 클라이언트의 요청 정보가 담긴 객체 **res (Response):** 클라이언트에게 응답을 보내기 위한 객체 **next:** 다음 미들웨어 함수를 실행시키기 위한 콜백 함수

```
const myMiddleware = (req, res, next) => {
  // 1. 필요한 작업을 수행
  console.log('미들웨어 동작!');
  
  // 2. 다음 미들웨어로 이동
  next(); 
};
```

미들웨어는 다음과 같은 작업을 수행할 수 있습니다.

1. **코드 실행:** 로깅, 데이터 분석 등 원하는 자바스크립트 코드를 실행합니다.
2. **요청 및 응답 객체 변경:** req.body에 데이터를 파싱해서 넣거나, res.header를 설정하는 등 객체를 조작할 수 있습니다.
3. **요청-응답 주기 종료:** res.send()나 res.json()을 호출하여 클라이언트에게 응답을 보내고 연결을 끊을 수 있습니다.
4. **다음 미들웨어 호출:** next()를 호출하여 스택 내의 다음 미들웨어로 제어권을 넘깁니다.

**주의할 점:** 만약 미들웨어가 응답을 보내지(3번) 않으면서 next()(4번)도 호출하지 않으면, 요청은 공중에 붕 뜬 상태가 되어 클라이언트는 영원히 응답을 기다리게 됩니다(Timeout 발생).

### 3. 미들웨어의 종류와 활용 예시

Express 개발에서 자주 사용되는 미들웨어의 종류는 다음과 같습니다.

#### 1) 애플리케이션 레벨 미들웨어

app.use()를 사용하여 등록하며, 모든 요청이나 특정 경로의 요청에 대해 실행됩니다.

- **예시:** 모든 요청에 대해 로그를 남기는 기능

#### 2) 빌트인(Built-in) 미들웨어

Express에 기본적으로 내장된 미들웨어입니다.

- **express.json():** 사용자가 보낸 JSON 데이터를 파싱하여 req.body에 넣어줍니다.
- **express.static():** 이미지, CSS 파일 같은 정적 파일을 제공합니다.

#### 3) 서드파티(Third-party) 미들웨어

다른 개발자들이 만들어 npm에 올린 외부 라이브러리입니다.

- **cors:** 다른 도메인에서의 요청을 허용하는 CORS 설정을 돕습니다.
- **morgan:** HTTP 요청 로그를 정교하게 남겨줍니다.

#### 4) 에러 핸들링 미들웨어

에러 처리를 전담하는 미들웨어로, 다른 미들웨어와 달리 (err, req, res, next) 4개의 인자를 받습니다. next(err)를 통해 전달된 에러를 받아 처리합니다.

### 마치며

Express로 서버를 만든다는 것은 곧 **필요한 미들웨어를 레고 블록처럼 조립하고, 내가 원하는 로직을 수행할 미들웨어를 직접 만드는 과정**이라고 해도 과언이 아닙니다.

요청이 들어와서 응답이 나갈 때까지의 흐름을 제어하는 이 미들웨어의 개념만 확실히 잡는다면, Express 개발이 훨씬 더 쉽고 자유로워질 것입니다
