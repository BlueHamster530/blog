안녕하세요.

백엔드 개발을 공부하다 보면 로컬 환경(내 컴퓨터)에서만 코드를 짜는 것이 아니라, 결국 AWS EC2 같은 원격 서버에 코드를 배포하고 운영해야 하는 시점이 옵니다. 이때 서버와 소통하기 위해 반드시 거쳐야 하는 관문이 바로 **SSH**입니다.

브라우저 주소창에 https를 입력해 보안 접속을 하듯, 서버(터미널)에 접속할 때 사용하는 보안 통신 규약인 SSH에 대해 핵심만 정리해 보겠습니다.

---

### 1. SSH란 무엇인가요?

SSH(Secure Shell)는 네트워크 상의 다른 컴퓨터에 로그인하거나, 원격 시스템에서 명령을 실행하고 파일을 복사할 수 있도록 해주는 응용 프로그램 또는 프로토콜입니다.

- **포트:** 기본적으로 **22번 포트**를 사용합니다. AWS EC2 인스턴스를 생성하고 보안 그룹(방화벽)을 설정할 때 'SSH - TCP - 22' 규칙을 열어주는 이유가 바로 이것입니다.
- **등장 배경:** 과거에는 **Telnet**이라는 방식을 사용했습니다. 하지만 Telnet은 데이터를 암호화하지 않고 평문(Plain Text)으로 전송했습니다. 즉, 해커가 중간에서 패킷을 가로채면 아이디와 비밀번호가 그대로 노출되는 치명적인 단점이 있었습니다. 이를 대체하기 위해 전송되는 모든 데이터를 암호화하는 SSH가 등장했습니다.

---

### 2. 핵심 원리: 키(Key) 기반 인증

SSH는 아이디와 비밀번호를 입력해서 접속할 수도 있지만, 실무에서는 보안 강화를 위해 **비대칭키 암호화 방식(Public Key / Private Key)**을 주로 사용합니다.

- **공개키 (Public Key, 자물쇠):** 누구나 가질 수 있습니다. 보통 접속하려는 서버(Server)의 authorized\_keys 파일에 저장해둡니다.
- **개인키 (Private Key, 열쇠):** 나만 가지고 있어야 합니다. 절대 남에게 유출되면 안 됩니다. 내 컴퓨터(Client)에 저장합니다.

**작동 방식 (핸드셰이크)**

1. 사용자가 서버에 접속을 요청합니다.
2. 서버는 공개키를 가지고 있는지 확인하기 위해, 공개키로 암호화된 난수(랜덤 데이터)를 사용자에게 보냅니다. ("이 자물쇠를 열 수 있는지 증명해봐.")
3. 사용자는 가지고 있는 개인키로 그 난수를 풉니다(복호화).
4. 제대로 풀어서 값을 서버에 보내면, 서버는 접속을 허용합니다.

---

### 3. 백엔드 개발자는 언제 SSH를 쓰나요?

크게 두 가지 상황에서 필수적으로 사용됩니다.

#### 1) 원격 서버 접속 (Deployment)

우리가 만든 Node.js나 Spring 서버를 배포하려면 리눅스 기반의 클라우드 서버에 접속해야 합니다. 이때 윈도우(PuTTY, PowerShell)나 맥(Terminal)에서 SSH를 통해 접속합니다.

```
# 기본 접속 (비밀번호 방식)
ssh username@192.168.0.1

# AWS 접속 (키 파일 방식)
# -i 옵션 뒤에 개인키 파일(.pem) 경로를 입력합니다.
ssh -i "my-key.pem" ubuntu@3.12.34.56
```

#### 2) Git / GitHub 사용

매번 git push를 할 때마다 아이디와 비밀번호를 입력하는 것은 매우 번거롭습니다. 내 컴퓨터에서 생성한 SSH 공개키를 GitHub 계정 설정(Settings > SSH and GPG keys)에 등록해두면, 비밀번호 입력 없이 안전하고 빠르게 코드를 주고받을 수 있습니다.

---

### 4. 주요 명령어

터미널에서 자주 사용하는 SSH 관련 명령어입니다.

- **접속하기:** ssh [계정명]@[서버주소]
- **키 생성하기:** ssh-keygen -t rsa (내 컴퓨터에서 공개키/개인키 쌍을 새로 만들 때 사용합니다.)
- **파일 전송(SCP):** scp [파일명] [계정명]@[서버주소]:[경로] (SSH 프로토콜을 이용해 로컬 파일을 원격 서버로 안전하게 복사할 때 사용합니다.)

---

### 5. 실무 팁: 권한 설정 문제 (Permission Denied)

AWS에서 받은 키 파일(my-key.pem)을 이용해 접속하려는데 WARNING: UNPROTECTED PRIVATE KEY FILE!이라는 에러가 뜨며 접속이 안 될 때가 있습니다.

이는 개인키 파일이 너무 개방되어 있어(누구나 읽을 수 있어서) SSH가 보안상 접속을 차단한 것입니다. 이때는 파일의 권한을 '나만 읽을 수 있도록' 변경해야 합니다.

```
# 리눅스/맥 기준 권한 변경 (나에게만 읽기 권한 부여)
chmod 400 my-key.pem
```

---

### 마치며

요약하자면 SSH는 **"내 컴퓨터와 서버 사이를 이어주는 암호화된 터널"**입니다. 이 터널을 통해 우리는 물리적으로 떨어져 있는 서버를 마치 내 눈앞에 있는 컴퓨터처럼 안전하게 제어할 수 있습니다.

서버 배포의 첫걸음인 SSH, 원리를 이해하고 사용하면 막연한 두려움이 사라질 것입니다.
