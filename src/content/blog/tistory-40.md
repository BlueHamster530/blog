안녕하세요.

데이터베이스, 특히 관계형 데이터베이스(RDB)를 공부하다 보면 가장 먼저 접하게 되는 두 가지 핵심 개념이 있습니다. 바로 Primary Key(기본키)와 Foreign Key(외래키)입니다.

이 두 키(Key)는 테이블 속에 저장된 수많은 데이터 중에서 특정 데이터를 정확히 찾아내고, 서로 다른 테이블의 데이터를 논리적으로 연결해 주는 매우 중요한 역할을 합니다.

오늘은 이 두 가지 키가 무엇이며, 어떤 차이점과 관계를 가지고 있는지 쉽게 정리해 보겠습니다.

### 1. Primary Key (기본키): 데이터의 유일한 식별자

Primary Key, 줄여서 PK라고 부르는 기본키는 테이블에 저장된 각 행(Row)을 서로 구분할 수 있게 해주는 유일한 식별자입니다.

데이터베이스 테이블에는 수많은 데이터가 쌓이게 되는데, 컴퓨터는 이 데이터 중 어떤 것이 우리가 찾는 데이터인지 정확히 알 수 있어야 합니다. 이때 사용하는 것이 바로 PK입니다.

#### PK의 대표적인 특징

1. 유일성 (Unique): 한 테이블 안에서 PK 값은 중복될 수 없습니다. 모든 데이터는 서로 다른 PK 값을 가져야 합니다.
2. Not Null: PK 값은 비어있을 수 없습니다. 반드시 값이 존재해야 합니다.
3. 불변성: 한 번 지정된 PK 값은 가급적 변하지 않아야 합니다.

#### 쉬운 예시: 주민등록번호

우리나라 국민에게는 주민등록번호라는 고유한 번호가 있습니다. 이름이 같은 동명이인은 있을 수 있어도, 주민등록번호가 같은 사람은 없습니다. 이처럼 사람(데이터)을 유일하게 구별해 주는 주민등록번호가 바로 PK의 역할과 같습니다.

웹 서비스에서는 주로 회원가입 시 부여되는 회원 ID(user\_id)나, 게시글 작성 시 자동으로 1씩 증가하며 붙는 게시글 번호(post\_id)가 PK로 사용됩니다.

### 2. Foreign Key (외래키): 테이블을 연결하는 다리

Foreign Key, 줄여서 FK라고 부르는 외래키는 다른 테이블의 PK를 참조하여 두 테이블을 연결해 주는 연결고리입니다.

관계형 데이터베이스(RDB)의 관계라는 말이 바로 이 외래키를 통해 성립됩니다. 외래키를 사용하면 데이터를 중복해서 저장할 필요 없이, 필요할 때마다 연결된 다른 테이블의 정보를 가져와 사용할 수 있습니다.

#### FK의 대표적인 특징

1. 참조 무결성: FK에는 아무 값이나 들어갈 수 없습니다. 반드시 참조하는 테이블(부모 테이블)의 PK에 실제로 존재하는 값만 저장할 수 있습니다. 없는 ID를 FK로 입력하려고 하면 데이터베이스는 에러를 발생시킵니다.
2. 중복 허용: PK와 달리 FK는 중복된 값을 가질 수 있습니다. (예: 한 명의 유저가 여러 개의 게시글을 작성할 수 있음)

#### 쉬운 예시: 쇼핑몰 주문 내역

쇼핑몰의 주문 테이블을 생각해 봅시다. 주문 테이블에는 누가 주문했는지 기록해야 합니다. 이때 주문자의 이름, 주소, 전화번호를 주문할 때마다 매번 적는 것은 비효율적입니다.

대신 회원 테이블의 PK인 회원 ID만 주문 테이블에 적어둡니다. 이때 주문 테이블에 적힌 회원 ID가 바로 Foreign Key입니다. 나중에 배송지 정보가 필요하면, 이 FK(회원 ID)를 이용해 회원 테이블에서 정보를 찾아오면 됩니다.

### 3. 정리: PK와 FK의 관계

이 두 키의 관계를 한 문장으로 정리하면 다음과 같습니다.

Primary Key(기본키)는 나 자신을 증명하는 신분증이고, Foreign Key(외래키)는 다른 사람(테이블)을 가리키는 손가락입니다.

- PK: 나는 이 테이블에서 유일한 존재야. (유일성)
- FK: 나는 저쪽 테이블의 특정 데이터를 가리키고 있어. (관계 형성)

이 두 가지 키를 올바르게 설정하는 것은 데이터의 무결성을 지키고 효율적인 데이터베이스 구조를 설계하는 가장 기초적이면서도 중요한 단계입니다.
