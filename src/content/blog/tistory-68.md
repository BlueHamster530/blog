안녕하세요.

백엔드 개발을 공부하며 AWS EC2 같은 클라우드 서버를 처음 띄웠을 때, 가장 먼저 마주치는 장벽이 바로 **'접속이 안 돼요'**입니다.

분명 서버는 켜져 있는데, 브라우저로 접속하면 뺑글뺑글 돌기만 하고, 터미널에서 SSH 접속을 시도해도 묵묵부답인 상황. 이럴 때 90% 이상의 원인은 바로 **인바운드(Inbound)와 아웃바운드(Outbound) 규칙 설정** 때문입니다.

AWS에서는 이를 **보안 그룹(Security Group)**이라고 부르며, 일종의 **가상 방화벽** 역할을 합니다. 오늘은 서버 배포의 필수 관문인 보안 그룹 규칙에 대해 확실하게 정리해 보겠습니다.

---

### 1. 인바운드 vs 아웃바운드: 우리 집 현관문으로 이해하기

가장 쉬운 비유는 서버를 '우리 집', 보안 그룹 규칙을 '현관문'이라고 생각하는 것입니다.

#### 1) 인바운드 규칙 (Inbound Rules) - "들어오는 것"

- **정의:** 외부(인터넷, 다른 서버)에서 내 서버로 들어오려는 트래픽에 대한 규칙입니다.
- **기본 설정:** 보안을 위해 기본적으로 **모두 차단(Deny All)** 되어 있습니다. 즉, 우리가 명시적으로 "이 포트는 열어줘"라고 허용한 것만 들어올 수 있습니다.
- **예시:** "사용자가 내 웹사이트(80번 포트)를 보러 들어온다", "내가 관리를 위해 SSH(22번 포트)로 서버에 접속한다."

#### 2) 아웃바운드 규칙 (Outbound Rules) - "나가는 것"

- **정의:** 내 서버에서 외부로 나가는 트래픽에 대한 규칙입니다.
- **기본 설정:** 보통 편의를 위해 **모두 허용(Allow All)** 되어 있습니다.
- **예시:** "서버가 npm install을 하기 위해 외부 저장소에서 파일을 다운로드한다", "서버가 소셜 로그인을 검증하기 위해 구글 API 서버를 호출한다."

---

### 2. 백엔드 주니어가 꼭 알아야 할 필수 설정

서버를 배포하려면 다음의 3가지 포인트는 반드시 숙지해야 합니다.

#### 1) 자주 쓰는 포트 번호와 용도

인바운드 규칙을 설정할 때 다음 포트 번호들은 외워두는 것이 좋습니다.

- **SSH (22):** 리눅스 서버 원격 접속 (관리자용)
- **HTTP (80):** 일반 웹사이트 접속
- **HTTPS (443):** 보안 웹사이트 접속 (SSL 인증서 적용 시)
- **DB (3306, 5432):** MySQL(3306), PostgreSQL(5432) 등 데이터베이스 접속

#### 2) 0.0.0.0/0의 의미와 보안 주의사항

소스(Source) IP를 0.0.0.0/0으로 설정하면 **"전 세계 모든 사람에게 개방한다"**는 뜻입니다.

- **웹 서버(80, 443):** 누구나 접속해야 하므로 0.0.0.0/0으로 엽니다.
- **SSH(22), DB(3306):** 절대 0.0.0.0/0으로 열면 안 됩니다. 전 세계 해커들의 비밀번호 대입 공격 대상이 됩니다. 반드시 **'내 IP(My IP)'**로만 제한하는 것이 정석입니다.

#### 3) "타임아웃(Time out)"은 99% 방화벽 문제

서버에 접속하거나 API를 호출했을 때, 즉시 '거절(Refused)'당하는 게 아니라 한참 동안 대기하다가 **Connection Timed Out** 에러가 난다면?

이는 십중팔구 인바운드 규칙에서 해당 포트를 안 열어준 것입니다. 서버가 요청을 받아서 "안 돼"라고 말한 게 아니라, 아예 방화벽(문)에서 막혀서 서버까지 도달조차 못한 상황입니다.

---

### 3. 심화 꿀팁

#### 1) 상태 저장(Stateful) 성질

AWS 보안 그룹은 **Stateful**합니다. 이것이 일반적인 방화벽 설정과 다른 가장 큰 특징입니다.

- 인바운드로 들어오는 요청이 허용되었다면, 그에 대한 **응답(나가는 데이터)은 아웃바운드 규칙과 상관없이 자동으로 허용**됩니다.
- 반대로, 아웃바운드로 나가는 요청이 허용되었다면, 그 응답으로 들어오는 데이터는 자동으로 허용됩니다.

따라서 "들어온 요청에 답변을 주기 위해 아웃바운드 규칙을 따로 열어야 하나?"라는 고민은 하지 않아도 됩니다.

#### 2) CIDR 표기법 맛보기 (/32 vs /0)

IP 주소 뒤에 붙는 /숫자는 IP 대역의 범위를 나타냅니다.

- **/32:** 정확히 그 IP 하나만 가리킵니다. (예: 192.168.1.1/32 -> 나만 접속 가능)
- **/0:** 모든 IP를 가리킵니다. (예: 0.0.0.0/0 -> 누구나 접속 가능)
- **/24:** 앞의 세 덩어리가 같은 IP 대역 (예: 같은 사무실, 같은 PC방 범위)

#### 3) DB 보안은 IP 대신 '보안 그룹 ID'로

RDS 같은 데이터베이스의 인바운드 규칙에는 IP 주소를 적는 대신, **'백엔드 서버(EC2)가 사용 중인 보안 그룹 ID'**를 적을 수 있습니다.

이렇게 설정하면 "이 보안 그룹 명찰을 단 EC2 서버들만 DB에 접속할 수 있어"라는 뜻이 됩니다. 서버의 IP가 바뀌어도 설정을 변경할 필요가 없고, 보안도 훨씬 강력해지는 팁입니다.

---

### 요약

1. **인바운드:** 들어오는 문. 필요한 포트만 열어라. (SSH는 꼭 내 IP만!)
2. **아웃바운드:** 나가는 문. 보통 다 열어둔다.
3. **에러 해결:** Timed Out이 뜨면 코드 보기 전에 인바운드 규칙부터 확인해라.

이 정도만 확실히 이해하고 있어도 초기 서버 세팅에서 겪는 네트워크 문제의 대부분을 스스로 해결하실 수 있을 것입니다.
