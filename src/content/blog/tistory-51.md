안녕하세요.

컴퓨터 과학계에는 유명한 농담이 하나 있습니다. "컴퓨터 과학에서 가장 힘든 일은 딱 두 가지다. 하나는 캐시 무효화(Cache Invalidation)이고, 다른 하나는 바로 이름 짓기(Naming)다."

변수명, 함수명, 클래스명 등을 지을 때 규칙 없이 마음대로 짓게 되면, 나중에 코드를 다시 보거나 동료와 협업할 때 가독성이 떨어져 큰 혼란을 겪게 됩니다.

오늘은 전 세계 개발자들이 약속처럼 사용하는 4가지 대표적인 표기법(Case)에 대해 알아보겠습니다.

### 1. 카멜 케이스 (Camel Case)

단어의 생김새가 마치 낙타(Camel)의 등과 같다고 하여 붙여진 이름입니다.

**규칙** 첫 글자는 소문자로 시작하고, 이어지는 단어의 첫 글자만 대문자로 표기합니다. 단어 사이에 공백이나 특수문자는 사용하지 않습니다.

**예시**

- userName
- isLoggedIn
- calculateTotalPrice

**주요 사용처** Java, C#, JavaScript 등 대부분의 프로그래밍 언어에서 **변수명**과 **함수(메소드)명**을 지을 때 표준으로 사용합니다.

### 2. 파스칼 케이스 (Pascal Case)

카멜 케이스와 비슷하지만, 첫 글자도 대문자로 시작한다는 점이 다릅니다. 쌍봉낙타의 모습을 닮았다고 해서 Upper Camel Case라고 부르기도 합니다.

**규칙** 모든 단어의 첫 글자를 대문자로 표기합니다.

**예시**

- UserService
- PlayerController
- FileInputStream

**주요 사용처** Java, Python, C# 등 대부분의 객체지향 언어에서 **클래스(Class)**나 **인터페이스(Interface)** 이름을 지을 때 사용합니다. "이것은 클래스(설계도)다"라는 것을 변수와 구분하기 위해 사용합니다.

### 3. 스네이크 케이스 (Snake Case)

단어 사이를 밑줄(\_)로 연결하는 방식이 마치 바닥을 기어가는 뱀(Snake)과 같다고 하여 붙여진 이름입니다.

**규칙** 모든 글자를 소문자로 쓰고, 단어 사이는 언더바(\_)로 연결합니다.

**예시**

- user\_id
- created\_at
- background\_image

**주요 사용처**

- **Python:** 파이썬에서는 변수명과 함수명에 카멜 케이스 대신 스네이크 케이스를 권장합니다.
- **데이터베이스(DB):** SQL에서 테이블 컬럼명을 지을 때 가장 많이 사용됩니다. (SQL은 대소문자 구분이 엄격하지 않은 경우가 많기 때문입니다.)

**참고: 스크리밍 스네이크 케이스 (Screaming Snake Case)** 스네이크 케이스의 일종으로, 모든 글자를 대문자로 쓰는 방식입니다. 예: MAX\_COUNT, API\_KEY 주로 프로그램 전체에서 변하지 않는 **상수(Constant)**를 정의할 때 사용합니다.

### 4. 케밥 케이스 (Kebab Case)

단어 사이를 하이픈(-)으로 연결한 모습이 꼬치에 꽂힌 케밥과 비슷하다고 하여 붙여진 이름입니다.

**규칙** 모든 글자를 소문자로 쓰고, 단어 사이는 하이픈(-)으로 연결합니다.

**예시**

- login-button
- main-content
- user-profile-page

**주요 사용처** 프로그래밍 언어 내부(Java, C 등)에서는 하이픈을 뺄셈(-) 연산자로 인식하기 때문에 변수명으로는 사용할 수 없습니다. 대신 **HTML 태그의 ID나 Class 속성**, **CSS 스타일 시트**, 그리고 **URL 주소**(www.blog.com/my-post-title)에서 표준처럼 사용됩니다.

### 요약 및 정리

언어와 환경에 따라 권장되는 규칙이 다릅니다.

1. **변수/함수:** 주로 **카멜 케이스** (myVariable) (단, 파이썬은 스네이크 케이스)
2. **클래스:** 주로 **파스칼 케이스** (MyClass)
3. **DB 컬럼:** 주로 **스네이크 케이스** (my\_column)
4. **상수:** 대문자 **스네이크 케이스** (MY\_CONSTANT)
5. **URL/CSS:** 주로 **케밥 케이스** (my-style)

개발은 혼자 하는 것이 아니라 팀으로 하는 것입니다. 팀 프로젝트나 회사의 스타일 가이드(Convention)를 따르는 것이 가장 좋은 명명 규칙임을 잊지 마세요.
