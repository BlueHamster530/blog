안녕하세요.

개인 프로젝트나 팀 프로젝트를 진행하다 보면, 업무의 흐름을 한눈에 파악하고 일정 관리를 효율적으로 하는 것이 무엇보다 중요합니다. 저는 이를 위해 주로 **칸반(Kanban) 시스템**을 활용하는데요.

칸반 시스템에 대해서는 아래 게시글을 확인해 주세요

[2025.12.31 - [개발] - 업무 흐름을 한눈에 파악하라: 칸반(Kanban) 시스템 완벽 가이드](https://bluehamster.tistory.com/52)

오늘은 올인원 생산성 도구인 **노션(Notion)**을 활용해 프로젝트 칸반 시스템을 처음부터 직접 구축하는 방법을 공유해 보려 합니다. 노션의 AI 기능이나 기본 템플릿을 사용할 수도 있지만, 직접 만들어보며 내 업무 스타일에 딱 맞는 환경을 구축해 보는 과정입니다.

*(작성 환경: Notion App Windows ver 6.3.2)*

---

### 1. 페이지 내 데이터베이스 생성

먼저 칸반 시스템을 구축할 빈 페이지를 준비해 주세요.

![](/blog/images/tistory-53/img1.png)

하단의 '시작하기 -> 데이터베이스' 메뉴를 이용할 수도 있지만, 원하는 위치에 유연하게 배치하기 위해 **인라인 데이터베이스**를 사용하겠습니다.

1. 빈 페이지에서 /데이터베이스를 입력합니다.
2. 나오는 메뉴 중 [데이터베이스 - 인라인]을 선택합니다.

![](/blog/images/tistory-53/img2.png)

이렇게 하면 페이지 내에 새로운 데이터베이스가 생성됩니다.

![](/blog/images/tistory-53/img3.png)

### 2. 다양한 보기(View) 형태 추가

데이터베이스 하나로 다양한 관점의 데이터를 보기 위해, 저는 보통 **표, 보드, 타임라인** 3가지를 기본으로 세팅합니다.

데이터베이스 제목 우측의 + 버튼을 눌러 **[보드]**와 **[타임라인]** 보기를 각각 추가해 주세요.

![](/blog/images/tistory-53/img4.png)

### 3. 프로젝트 맞춤 속성(Property) 추가

이제 프로젝트 성격에 맞는 속성(컬럼)들을 정의할 차례입니다. 데이터베이스 우측 상단 ... 버튼 옆의 **[새로 만들기]** 버튼 좌측 설정(점 3개)을 누른 뒤, **[속성]** 메뉴로 진입합니다.

하단의 + 새 속성 버튼을 눌러 필요한 항목들을 추가해 줍니다.

속성 편집에 들어가면 아래 이미지와 같이 현재 가지고 있는 속성 리스트와 함께 하단에 "+ 새 속성" 버튼이 있습니다.

![](/blog/images/tistory-53/img5.png)![](/blog/images/tistory-53/img6.png)![](/blog/images/tistory-53/img7.png)

#### 💡 추천 속성 리스트

기본적인 속성 외에, 개발 협업 시 유용한 속성들을 추가로 구성해 보세요.

- **이름 (제목):** 업무의 제목
- **상태 (상태):** 단순히 진행 중/완료가 아닌 실제 개발 프로세스를 반영해 보세요.
  - *팁: 시작 전 → 진행 중 → 코드 리뷰(PR) → QA(테스트) → 완료*
- **유형 (선택):** 개발 / 버그 수정 / 기획 / 디자인 등
- **우선순위 (선택):** 낮음 / 보통 / 높음 / 긴급
- **담당자 (사람):** 업무를 수행할 담당자
- **기간 (날짜):** 시작일과 종료일
- **PR 링크 (URL):** 해당 작업의 깃허브 Pull Request 주소 기록
- **관련 이슈 (관계형):** 기획 문서나 연관된 다른 티켓을 연결

### 4. 업무 레이아웃 최적화

속성을 모두 만들었다면, 업무 카드를 클릭했을 때 보이는 화면 구성을 다듬어 보겠습니다. 업무 페이지 우측 상단의 ... 버튼을 클릭한 후 **[레이아웃 사용자 지정]**으로 들어갑니다.

![](/blog/images/tistory-53/img8.png)

여기서 속성의 표시 여부나 순서를 변경할 수 있습니다.

![](/blog/images/tistory-53/img9.png)

- **팁:** 저는 '페이지 댓글' 등의 순서를 조정하거나, 중요한 속성만 상단에 노출되도록 설정하여 가독성을 높입니다. 드래그 앤 드롭으로 간편하게 순서를 바꿀 수 있습니다.

### 5. 업무 효율을 높이는 '템플릿' 제작

반복되는 업무 형식을 미리 지정해 두면 협업 시 통일성을 갖출 수 있고 시간도 절약됩니다. 예시로 **'버그 수정'** 템플릿을 만들어 보겠습니다.

1. 데이터베이스 우측 상단 새로 만들기 버튼 옆의 화살표(v)를 클릭합니다.
2. **[+ 새 템플릿]**을 선택합니다.

![](/blog/images/tistory-53/img10.png)![](/blog/images/tistory-53/img11.png)

1. 템플릿 편집 화면에서 '유형' 속성을 **[버그 수정]**으로 미리 지정해 둡니다.
2. 본문에 버그 리포팅 양식(발생 경로, 증상, 재현 방법 등)을 미리 작성해 둡니다.

![](/blog/images/tistory-53/img12.png)

이제 새로운 업무를 생성할 때, 하단에 나타나는 템플릿 버튼만 누르면 속성과 본문 양식이 자동으로 채워집니다.

이제 새로운(비어있는) 업무를 열어보시면 이미지와 같이 버그 수정 템플릿을 선택할 수 있습니다.

![](/blog/images/tistory-53/img13.png)![](/blog/images/tistory-53/img14.png)

**💡 꿀팁: 기본 템플릿 설정** 만약 '개발' 업무가 가장 많다면, 해당 템플릿의 ... 버튼을 눌러 **[기본값으로 설정]** 해두세요. 매번 템플릿을 고르지 않아도 자동으로 양식이 적용되어 편리합니다.

### 6. 보드 뷰 활용하기 (To-Do List 및 필터링)

이제 본격적으로 시각적인 관리를 해볼까요? 보기 형식을 **[보드]**로 변경합니다.

보드 뷰는 업무의 상태(시작 전, 진행 중, 완료) 별로 카드를 볼 수 있어 직관적인 **To-Do List** 관리가 가능합니다. 업무가 진행됨에 따라 카드를 드래그하여 옆 칸으로 옮기기만 하면 상태가 업데이트됩니다.

데이터베이스에서 보기 형태를 기존 표 가 아닌 보드를 선택해주세요

![](/blog/images/tistory-53/img15.png)

하지만 프로젝트가 길어지면 완료된 카드가 너무 많아져 보드가 지저분해집니다. 이때 **필터와 정렬** 기능을 활용해 보세요.

- **필터:** [상태] → [완료] → [값과 같지 않음]을 선택하면, 현재 진행 중인 업무만 깔끔하게 볼 수 있습니다.
- **정렬:** [우선순위] → [오름차순/내림차순]을 적용하면 긴급한 업무가 맨 위에 표시되어 놓치지 않을 수 있습니다.

![](/blog/images/tistory-53/img16.png)

### 7. 타임라인 활용하기 (일정 및 의존성 관리)

전체적인 프로젝트 일정을 파악할 때는 **[타임라인]** 보기가 유용합니다.

- **일정 조절:** 막대의 양 끝을 잡고 드래그하면 시작일과 종료일을 쉽게 변경할 수 있습니다.
- **의존성 연결:** 업무 막대 끝의 노란색 점을 드래그하여 다른 업무와 연결하면 화살표가 생깁니다. 이는 **선행 작업과 후속 작업의 관계**를 나타내며, 업무의 흐름(Flow)을 파악하는 데 큰 도움이 됩니다.

![](/blog/images/tistory-53/img17.png)
![](/blog/images/tistory-53/img18.png)

### 8. 프로젝트 진척률 시각화 (차트 활용)

프로젝트가 얼마나 진행되었는지 수치가 아닌 그래프로 한눈에 파악하고 싶다면 **차트 보기** 기능을 활용해 보세요.

1. 앞서 보기를 추가했던 것처럼, 데이터베이스 상단의 + 버튼을 눌러 **[차트]** 보기를 생성합니다.![](/blog/images/tistory-53/img19.png)
2. 우측 상단의 설정 메뉴에서 **차트 유형**을 **[도넛]**으로 변경합니다.
3. '그룹화 기준'을 '상태'로 설정하면, 전체 업무 중 '완료'된 업무가 얼마나 되는지 비율로 쉽게 확인할 수 있습니다.

![](/blog/images/tistory-53/img20.png)

색상이나 데이터 표시 옵션을 프로젝트 성격에 맞게 조절하면, 별도의 보고서 없이도 훌륭한 **프로젝트 대시보드**가 완성됩니다.

### 9. 마무리

지금까지 노션의 기능을 200% 활용하여 개발자 친화적인 칸반 시스템을 구축해 보았습니다.

단순히 나열하는 것을 넘어, **PR 링크를 관리하고 코드 리뷰 단계를 시각화**하는 등 여러분의 팀 색깔에 맞춰 시스템을 발전시켜 보세요. 잘 만들어진 칸반 보드가 프로젝트의 성공 확률을 높여줄 것입니다.
