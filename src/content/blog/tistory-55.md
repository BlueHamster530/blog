안녕하세요.

백엔드 개발을 공부하며 프로젝트를 진행하다 보면 반복적이고 시간 소모적인 작업에 부딪힐 때가 많습니다. 그중 하나가 바로 API 명세서인 **Swagger(스웨거)** 작성입니다.

저는 최근 프로젝트에서 생성형 AI를 활용해 이 작업을 효율화했습니다. 단순히 "이거 만들어줘"라고 시키는 것이 아니라, AI를 마치 제 부사수나 동료처럼 리딩하며 협업하는 방식을 사용했습니다.

오늘은 제가 실제로 사용한 **AI 협업 전략 5가지**와, 이를 통해 배운 **보편적인 AI 활용 팁**, 그리고 놓치지 말아야 할 **보완점**을 공유합니다.

![](/blog/images/tistory-55/img1.png)

---

### 1. 나의 AI 활용 사례: Swagger 문서화 프로젝트

저는 nestia나 swagger-cli 같은 자동화 도구로 커버하기 힘든 커스텀 명세 작업이 필요했습니다. 이때 무작정 AI에게 코드를 던지는 대신 다음과 같은 프로세스를 거쳤습니다.

#### 1) 명확한 지도 그리기 (Context Engineering)

대화 시작부터 전체 프로젝트의 폴더 구조(modules, auth, cars 등)를 텍스트로 정리해서 주입했습니다. AI가 지금 자신이 어디서 작업하는지 \*\*맥락(Context)\*\*을 이해하게 만들어, 엉뚱한 경로를 참조하는 환각 현상을 방지했습니다.

#### 2) 정답지 보여주기 (Few-Shot Prompting)

"그냥 잘 만들어줘"가 아니라, 이미 제가 잘 작성해 둔 contract-swagger.ts의 특정 라인(176-186)을 예시로 보여줬습니다. "이 스타일대로 작성해"라고 기준(Reference)을 주니, AI가 제 코딩 스타일을 모방하여 이질감 없는 코드를 짜주었습니다.

#### 3) 유연한 대처 (Human-in-the-Loop)

AI가 노션 링크를 읽지 못하는 보안 이슈가 발생했을 때, 당황하지 않고 필요한 명세 데이터(Request/Response Body)만 텍스트로 긁어서 제공했습니다. 도구의 한계를 탓하기보다 제가 **데이터 브리지** 역할을 수행하여 작업을 끊김 없이 이어갔습니다.

#### 4) 분할 정복 (Divide and Conquer)

전체 API를 한 번에 요청하면 AI의 성능이 급격히 떨어집니다. 저는 Auth 모듈, Cars 모듈, Customers 모듈 순으로 **작업을 잘게 쪼개서** 요청했고, 각 결과물을 검수한 뒤 합치는 방식을 택했습니다.

#### 5) 학습 도구로 활용

단순히 코드를 받는 것에 그치지 않았습니다. launch.json 설정 중 이해가 안 가는 부분이 생기면, 해당 코드를 AI에게 설명해달라고 역으로 질문하여 제 지식으로 체화했습니다.

### 2. 개발자를 위한 보편적인 AI 활용 팁 (Best Practices)

제 경험을 통해 정리한, 실패하지 않는 AI 활용 공식입니다.

#### 구체적인 상황(Context)을 먼저 주입하세요

질문하기 전에 내가 사용하는 언어, 프레임워크 버전, 폴더 구조, 사용 중인 라이브러리 등을 먼저 알려주세요. AI의 답변 퀄리티가 달라집니다.

#### 추상적인 형용사 대신 '코드 예시'를 주세요

"깔끔하게 짜줘"라는 말은 모호합니다. 대신 "변수명은 카멜 케이스로, 에러 처리는 Try-Catch 대신 인터셉터를 사용하는 방식으로 짜줘"와 같이 구체적인 지침이나 예시 코드를 제공하세요.

#### AI는 '주니어 개발자'라고 생각하세요

AI는 똑똑하지만 실수를 합니다. 한 번에 너무 많은 일을 시키면 놓치는 부분이 생깁니다. 함수 하나, 클래스 하나 단위로 쪼개서 일을 시키고, 반드시 시니어가 코드 리뷰를 하듯 검증해야 합니다.

### 3. 보완 및 주의할 점 (Security & Validation)

AI를 적극적으로 활용하되, 개발자로서 반드시 지켜야 할 선이 있습니다.

#### 데이터 보안 (Data Privacy) - 가장 중요!

AI에게 코드를 질문할 때 **API Key, DB 비밀번호, AWS 자격 증명, 사내 비공개 IP** 등 민감한 정보가 포함되어 있는지 반드시 확인해야 합니다. 실수로라도 이런 정보가 프롬프트에 들어가면 외부로 유출될 위험이 있습니다. 환경 변수(.env)로 분리하거나 가상의 값(\*\*\*\*\*\*)으로 마스킹하여 질문하는 습관을 들여야 합니다.

#### 코드 검증과 책임 (Verification)

AI가 짠 코드는 실행은 되지만 최적화가 안 되어 있거나, 보안 취약점(SQL Injection 등)이 있을 수 있습니다. 또한, 존재하지 않는 라이브러리를 import 하는 경우도 있습니다. \*\*"AI가 짠 코드는 반드시 틀릴 수 있다"\*\*는 전제하에, 모든 라인을 직접 읽고 테스트 코드를 통해 검증해야 합니다.

#### 최신성 확인 (Legacy Code Warning)

AI 모델의 학습 시점에 따라, 이미 **Deprecated(사용 중단)** 된 함수나 문법을 추천할 수 있습니다. 공식 문서를 교차 검증하여 최신 버전에 맞는 코드인지 확인하는 과정이 필요합니다.

### 마치며

AI는 개발자를 대체하는 것이 아니라, 개발자의 생산성을 폭발적으로 높여주는 **'광속의 페어 프로그래밍 파트너'**입니다.

하지만 그 파트너를 얼마나 잘 부리는지는 전적으로 여러분의 **질문 능력(Prompt Engineering)**과 **기본기(CS 지식)**에 달려 있습니다.

오늘 공유한 팁들을 활용해 여러분도 AI를 리딩하는 주도적인 개발자가 되시길 바랍니다.
