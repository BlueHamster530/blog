개발자라면 누구나 한 번쯤 겪는 공포가 있습니다. 바로 아침에 눈을 떴을 때 날아와 있는 **'AWS 요금 청구서'**죠. 😱

"단지 Node.js와 Express로 만든 간단한 커뮤니티 API 서버 하나 띄웠을 뿐인데... 왜 내 통장이 텅장이 되어가는 걸까?"

이런 고민을 해보셨거나, AWS의 태평양처럼 넓고 복잡한 콘솔 창(VPC, 서브넷, 보안 그룹...) 앞에서 길을 잃은 적이 있다면, 오늘 소개할 **AWS Lightsail**이 여러분의 구원자가 될 수 있습니다.

---

## 1. AWS Lightsail, 넌 대체 누구냐?

AWS Lightsail을 한마디로 정의하자면 **"월정액으로 즐기는 클라우드계의 풀옵션 원룸"**입니다.

비유를 하나 들어볼게요.

- **AWS EC2 (기존 클라우드):** 넓은 공터를 사고, 직접 시멘트를 바르고, 수도관을 연결하고, 전기 공사를 해야 합니다. 자유도는 무한대지만, 건축 지식(인프라 지식)이 없으면 집 짓다가 쓰러집니다. 게다가 수도관을 얼마나 썼는지 초 단위로 계산해서 요금을 청구하죠.
- **AWS Lightsail:** 침대, 책상, 와이파이가 모두 갖춰진 풀옵션 원룸입니다. 보증금 없이 '월 5달러' 딱 정해진 월세만 내면 됩니다. 몸(코드)만 들어가서 바로 살면(배포하면) 됩니다.

Lightsail은 가상 사설 서버(VPS)로, 컴퓨팅, 스토리지, 데이터 전송 요금이 하나의 패키지로 묶여 있어 **가격 예측이 100% 가능**하다는 엄청난 장점이 있습니다.

---

## 2. 왜 Lightsail을 써야 할까? (장점)

1. **가성비와 예측 가능한 요금:** 한 달에 커피 한 잔 값(약 $3.5 ~ $5)으로 나만의 Linux 서버를 가질 수 있습니다. 트래픽 요금 폭탄 걱정 없이 꿀잠을 잘 수 있죠.
2. **3번의 클릭으로 끝나는 배포:** OS(Ubuntu, CentOS 등)는 물론이고, Node.js, WordPress, LAMP 스택 등이 이미 설치된 이미지를 제공합니다.
3. **AWS 생태계와의 연결성:** 장사가 잘 되어서 원룸(Lightsail)이 좁아지면? 언제든지 AWS의 대저택(EC2)으로 짐을 싸서 이사(마이그레이션)할 수 있는 기능을 제공합니다.

## 3. Lightsail vs EC2 vs DigitalOcean (비교 분석)

"그럼 무조건 Lightsail이 짱인가요?"

세상에 은통수는 없듯, 상황에 맞는 도구를 선택하는 것이 엔지니어의 숙명입니다.

|  |  |  |  |
| --- | --- | --- | --- |
| **비교 항목** | **AWS Lightsail** | **AWS EC2** | **DigitalOcean / Linode** |
|  |  |  |  |
| --- | --- | --- | --- |
| **타겟 유저** | 주니어 개발자, 스타트업, 개인 블로거 | 미드~시니어 엔지니어, 대규모 기업 | 개발자 중심, 깔끔한 UI 선호자 |
| **요금 체계** | 고정 요금제 (월액 패키지) | 종량제 (사용한 만큼 초당 과금) | 고정 요금제 (Lightsail과 유사) |
| **학습 곡선** | 🟢 매우 쉬움 | 🔴 어려움 (네트워크 지식 필수) | 🟡 쉬움 ~ 보통 |
| **확장성/커스텀** | 제한적 (정해진 스펙 안에서 사용) | 무한함 (오토스케일링, 로드밸런서 등) | 우수함 (개발자 친화적 도구 많음) |

- **DigitalOcean이나 Linode와의 차이점?**
- 사실 단일 서버만 띄운다면 DigitalOcean도 매우 훌륭합니다. 하지만 나중에 유저가 늘어나서 S3(이미지 스토리지), RDS(관리형 DB), Route53(도메인) 등 **AWS의 핵심 서비스들과 연동**해야 할 때, 동일한 AWS 계정 내에 있는 Lightsail이 VPC 피어링 등을 통해 훨씬 매끄럽게 확장할 수 있습니다.

## 4. 그래서, 언제 쓰면 좋을까요?

- **🟢 Lightsail을 강력 추천하는 경우:**
  - 이제 막 백엔드 개발을 공부하며 내 코드를 퍼블릭하게 띄워보고 싶은 학생
  - Node.js, Express, PostgreSQL 등을 활용해 소규모 커뮤니티나 게시판 프로젝트를 운영할 때
  - Docker 컨테이너 하나만 간단하게 띄워놓고 싶을 때
  - 외주 작업으로 간단한 랜딩 페이지나 워드프레스 블로그를 만들어줘야 할 때
- **🔴 Lightsail을 피해야 하는 경우:**
  - 트래픽이 폭포수처럼 쏟아져서 서버가 10대, 20대씩 자동으로 늘어나야 할 때 (Auto Scaling 필요)
  - 마이크로서비스 아키텍처(MSA)를 구축하여 복잡한 인프라 설계가 필요할 때

## 3. Lightsail 삽질기 주의보 (이건 꼭 주의하세요!)

처음 Lightsail을 도입하면서 몇 가지 뼈아픈 시행착오를 겪을 수 있습니다.. 여러분은 같은 실수를 하지 않으시길 바라며 주의사항을 공유드립니다.

### 🚨 삽질 1: 고정 IP(Static IP)를 안 붙여서 발생한 참사

Lightsail 인스턴스를 생성하면 기본적으로 '동적 퍼블릭 IP'가 할당됩니다. 처음에 신나서 도메인까지 다 연결해 놨는데, 서버 설정을 바꾸느라 인스턴스를 재부팅했더니 IP가 바뀌어버릴 수 있습니다. (DNS 설정이 다 꼬여버립니다.)   
**해결책:** 인스턴스 생성 직후, 네트워킹 탭에서 **반드시 '고정 IP(Static IP)'를 먼저 생성하고 연결**하세요. Lightsail에서는 인스턴스에 연결된 고정 IP는 추가 요금이 과금되지 않습니다!

### 🚨 삽질 2: 프리티어(RAM 1GB)의 한계, 메모리 부족(OOM)으로 서버 다운

월 5달러짜리 깡통(RAM 1GB) 인스턴스에 Node.js 환경을 세팅하고, Prisma 같은 ORM을 써서 빌드를 돌리거나 Docker 컨테이너를 여러 개 띄우다 보니 서버가 멈춰버릴 수 있습니다. 메모리 초과(Out Of Memory)로 프로세스가 죽는 것이죠.   
**해결책:** RAM을 올리면 월 요금이 비싸지므로, 리눅스의 Swap 메모리(가상 메모리)를 설정하여 해결하는 방법을 추천드립니다. SSD 용량 중 2GB 정도를 RAM처럼 사용하게 만들면, 빌드 시 뻗어버리는 현상을 막을 수 있습니다.

### 🚨 삽질 3: 쓸데없는 방화벽(포트) 개방

Lightsail은 콘솔의 '네트워킹' 탭에서 방화벽 규칙을 추가합니다. 처음에 테스트한다고 3000(Node), 8080 등 모든 포트를 열어둔다면, 보안상 매우 위험합니다.   
**해결책:** Nginx를 리버스 프록시로 앞단에 세우고, Lightsail 방화벽에서는 80(HTTP)과 443(HTTPS), 그리고 특정 IP에서만 접속 가능한 22(SSH) 포트만 열어두는 것이 베스트 프랙티스입니다.
