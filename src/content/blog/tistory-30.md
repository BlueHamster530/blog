안녕하세요!

개발자로서 탄탄한 기본기를 갖추는 것은 매우 중요합니다. 수많은 개념이 있지만, 오늘은 그중에서도 '프로그램을 어떻게 설계할 것인가'에 대한 **프로그래밍 패러다임**(절차지향 vs 객체지향)과, '비동기 작업을 어떻게 처리할 것인가'에 대한 **프로미스(Promise)**의 핵심 개념을 알아보겠습니다.

이 두 가지는 각각 코드의 **구조**와 **실행 흐름**을 이해하는 데 필수적인 요소들입니다.

---

### 1. 절차지향 프로그래밍 (Procedural Programming)

절차지향 프로그래밍은 데이터가 아닌, **실행되는 절차와 순서**를 중심으로 프로그램을 설계하는 프로그래밍 패러다임입니다. 물이 위에서 아래로 흐르는 것처럼 정해진 순서에 따라 함수를 순차적으로 호출하여 작업을 처리합니다.

대표적인 언어로 **C언어**가 있습니다.

#### 장점

- **빠른 실행 속도:** 컴퓨터의 처리 구조와 유사하여 객체를 만들고 관리하는 과정이 없으므로 실행 속도가 빠릅니다.
- **직관적인 흐름:** 코드의 실행 순서가 명확하게 보이기 때문에 초기에 이해하기 쉽습니다.

#### 단점

- **낮은 유지보수성:** 프로그램 규모가 커질수록 코드의 흐름을 파악하기 어려워지며, 데이터와 함수가 분리되어 있어 데이터 구조가 변경되면 관련된 모든 함수를 일일이 수정해야 합니다. 이는 **'스파게티 코드'**를 유발할 수 있습니다.
- **낮은 코드 재사용성:** 각 함수가 특정 기능에 강하게 의존하고 있어, 다른 프로그램에서 해당 기능을 가져와 재사용하기 어렵습니다.

---

### 2. 객체지향 프로그래밍 (Object-Oriented Programming, OOP)

객체지향 프로그래밍은 실제 세상의 사물이나 개념을 **'객체(Object)'**라는 단위로 보고, 이 객체들의 상호작용을 통해 프로그램을 설계하는 프로그래밍 패러다임입니다.

관련된 **데이터(속성)**와 그 데이터를 처리하는 **함수(메서드)**를 하나의 '객체'로 묶어 관리하는 것이 핵심입니다. 대표적인 언어로 **Java, Python, C++, C#** 등이 있습니다.

#### 주요 특징 (4대 특성)

1. **캡슐화 (Encapsulation):** 데이터와 메서드를 하나로 묶고, 외부의 직접적인 접근을 제한하여 데이터의 무결성을 보장합니다.
2. **상속 (Inheritance):** 부모 클래스의 특징을 자식 클래스가 물려받아 코드의 중복을 줄이고 재사용성을 높입니다.
3. **다형성 (Polymorphism):** 동일한 이름의 메서드가 객체에 따라 다른 방식으로 동작하게 하여 코드의 유연성을 높입니다.
4. **추상화 (Abstraction):** 불필요한 세부 정보는 숨기고, 중요한 핵심 기능에만 집중하여 모델을 단순화합니다.

#### 장점

- **높은 코드 재사용성과 생산성:** 상속과 같은 기능을 통해 기존 코드를 쉽게 재사용하고 확장할 수 있습니다.
- **용이한 유지보수:** 코드가 기능별로 모듈화(객체화)되어 있어, 특정 기능을 수정하거나 추가할 때 해당 객체만 집중적으로 관리하면 되므로 유지보수가 편리합니다.

#### 단점

- **설계의 복잡성:** 프로그램을 만들기 전, 객체를 식별하고 각 객체의 역할과 관계를 명확히 설계해야 하므로 초기 설계 단계에 많은 시간과 노력이 필요합니다.
- **상대적으로 느린 실행 속도:** 절차지향에 비해 객체를 만들고 상호작용하는 과정에서 추가적인 처리 시간이 소요될 수 있습니다.

---

### 3. 절차지향 vs 객체지향: 핵심 차이

두 패러다임의 가장 큰 차이는 **'데이터와 그 데이터를 처리하는 행위(함수)를 하나로 묶어서 관리하는가'**에 있습니다.

- **절차지향 프로그래밍**은 빠른 실행 속도가 중요하거나, 규모가 작고 단순한 프로그램(예: 임베디드 시스템, 과학 계산 프로그램)에 유리합니다.
- **객체지향 프로그래밍**은 여러 개발자가 협업하는 대규모 프로젝트나, 지속적인 기능 개선과 유지보수가 중요한 애플리케이션 개발에 더 적합합니다.

---

### 4. 프로미스(Promise)의 3가지 상태

프로미스(Promise)는 자바스크립트에서 비동기 작업의 최종 완료 또는 실패를 나타내는 객체입니다. 프로미스는 다음 3가지 상태 중 하나를 가집니다.

1. **대기 (Pending):** 이행하지도, 거부하지도 않은 초기 상태. 비동기 작업이 아직 완료되지 않았음을 의미합니다.
2. **이행 (Fulfilled):** 연산이 성공적으로 완료됨. 작업이 성공했고, 결과값을 사용할 수 있는 상태입니다. (.then()으로 연결)
3. **거부 (Rejected):** 연산이 실패함. 작업이 실패했고, 실패 이유(에러)가 있는 상태입니다. (.catch()로 연결)

**식당으로 비유**하자면 다음과 같습니다.

- **대기 (Pending):** 음식을 주문하고 기다리는 상태
- **이행 (Fulfilled):** 요리가 성공적으로 나온 상태
- **거부 (Rejected):** 재료 소진 등으로 음식이 나올 수 없다는 소식을 들은 상태

---

### 마치며

오늘은 프로그램의 큰 그림을 그리는 **프로그래밍 패러다임(절차지향, 객체지향)**과, 자바스크립트 비동기 처리의 핵심인 **프로미스의 3가지 상태**에 대해 알아보았습니다.

OOP와 POP의 차이를 이해하면 코드 구조를 설계하는 시야가 넓어지고, 프로미스의 상태를 명확히 알면 비동기 로직을 더 견고하게 작성할 수 있습니다.
