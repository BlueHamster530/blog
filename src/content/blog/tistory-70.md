안녕하세요.

프로젝트를 진행하며 이미지 업로드를 위해 AWS S3를 구축하다 보면, 프론트엔드에서 이미지가 보이지 않아 **'권한 설정(Permission)'**을 만지게 됩니다.

구글링을 통해 "S3 전체 공개 정책"을 검색하면 아래와 같은 JSON 코드를 발견하게 되는데요.

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::bluehamster-codeit-6th-sprint-s3/*"
    }
  ]
}
```

공부를 하던 중 이 JSON이 정확히 어떤 뜻인지, 왜 이렇게 써야 하는지 궁금점이 생겼습니다.

오늘은 이 정책 구문을 한 줄 한 줄 뜯어보겠습니다.

### 1. Version: "2012-10-17"

```
"Version": "2012-10-17"
```

- **의미:** AWS 정책 언어(문법)의 버전을 뜻합니다.
- **해설:** "2012년? 너무 옛날 버전 아니야?"라고 생각할 수 있지만, **고정값**입니다. AWS IAM 정책 문법이 2012년 10월 17일에 확정된 이후 지금까지 표준으로 사용되고 있습니다.
- **주의:** 마음대로 현재 날짜("2024-02-08")로 바꾸면 에러가 납니다. 그냥 **"항상 이 값을 쓴다"**고 외워두세요.

### 2. Statement (규칙의 묶음)

```
"Statement": [ ... ]
```

- 정책의 핵심 내용이 들어가는 곳입니다. 대괄호([])로 되어 있으니 여러 개의 규칙을 나열할 수도 있습니다.

### 3. Sid: "PublicReadGetObject" (이름표)

```
"Sid": "PublicReadGetObject"
```

- **의미:** Statement ID의 약자로, 이 규칙의 **'별명'** 혹은 **'설명'**입니다.
- **해설:** 시스템이 해석하는 코드가 아니라, **사람이 읽기 좋으라고 붙인 이름표**입니다. "이 규칙은 공개 읽기 전용이야"라고 써놓은 것이죠.
- **활용:** MyProjectImageOpenPolicy 처럼 마음대로 지어도 기능에는 영향이 없습니다.

### 4. Effect: "Allow" (허용할까, 말까?)

```
"Effect": "Allow"
```

- **의미:** 해당 규칙을 **허용(Allow)**할지, **거부(Deny)**할지 결정합니다.
- **해설:** 우리는 외부에서 이미지를 볼 수 있게 해줘야 하므로 Allow를 사용했습니다. 보안을 위해 특정 IP를 차단할 때는 Deny를 쓰기도 합니다.

### 5. Principal: "\*" (누구에게?)

```
"Principal": "*"
```

- **의미:** 이 권한을 **'누구'**에게 줄 것인가를 지정합니다.
- **해설:** \* (와일드카드)는 **"모든 사람(익명의 사용자 포함)"**을 의미합니다.
- **활용:** 쇼핑몰 상품 이미지처럼 로그인 안 한 사람도 봐야 하는 경우 \*를 씁니다. 만약 특정 관리자(IAM User)에게만 주고 싶다면 그 사용자의 ARN을 적어야 합니다.

### 6. Action: "s3:GetObject" (무엇을?)

```
"Action": "s3:GetObject"
```

- **의미:** 허용된 대상이 **'어떤 행동'**을 할 수 있는지 정의합니다.
- **해설:** s3:GetObject는 S3 버킷에 있는 객체(파일)를 **'가져오기(다운로드/읽기)'**만 할 수 있다는 뜻입니다.
- **보안:** s3:DeleteObject(삭제)나 s3:PutObject(업로드) 권한은 없으므로, 외부인이 파일을 맘대로 지우거나 올릴 수는 없습니다. 안전하죠!

### 7. Resource: "arn:aws:s3:::.../\*" (어디에?)

```
"Resource": "arn:aws:s3:::대충내s3버킷/*"
```

- **의미:** 이 규칙이 적용될 대상(범위)'을 지정합니다. AWS에서는 모든 자원을 ARN(Amazon Resource Name)이라는 고유 ID로 관리합니다.
- **해설:**
  - 대충내s3버킷: 버킷 이름입니다.
  - /\*: **매우 중요합니다.** 해당 버킷 **'안에 있는 모든 파일'**을 의미합니다. 만약 /image/\*라고 쓰면 image 폴더 안의 파일만 공개됩니다.

---

### 요약: 한 문장으로 해석하기

이 JSON 정책을 사람의 말로 번역하면 다음과 같습니다.

> **"이 버킷(Resource) 안에 있는 모든 파일(/\*)에 대해서,** \**전 세계 누구나(Principal: *),** **파일을 읽어가는 행위(Action: GetObject)를** **허용(Effect: Allow)합니다."**

### 마치며

S3 버킷 정책은 한번 설정해두면 잘 건드리지 않지만, 잘못 설정하면 **보안 사고(데이터 유출)**나 **서비스 장애(이미지 엑박)**로 이어질 수 있는 중요한 부분입니다.

이제 JSON 코드를 볼 때 단순히 복사하지 말고, "아, 이건 누구에게 어떤 권한을 주는 거구나"라고 해석하며 적용해 보세요. 백엔드 개발자의 인프라 이해도가 한 층 높아질 것입니다.
