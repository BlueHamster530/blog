안녕하세요.

웹 개발을 시작하면 가장 먼저 배우는 데이터베이스는 보통 MySQL, Oracle, PostgreSQL과 같은 관계형 데이터베이스(RDB)입니다. 최근에는 다양한 형태의 데이터베이스가 등장했지만, 여전히 금융, 쇼핑몰, 예약 시스템 등 중요한 데이터를 다루는 웹 서비스의 90% 이상은 RDB를 메인 저장소로 사용하고 있습니다.

단순히 데이터를 저장하고 불러오는 것이 목적이라면 엑셀 파일이나 텍스트 파일로도 충분할 텐데, 왜 우리는 복잡한 SQL 문법을 배워가며 RDB를 고집하는 걸까요?

가장 큰 이유는 바로 데이터 무결성(Data Integrity)을 보장하기 위해서입니다.

### 1. 데이터 무결성이란 무엇인가?

데이터 무결성이란 데이터의 정확성, 일관성, 유효성이 유지되는 상태를 말합니다. 쉽게 말해, 저장된 데이터가 오염되지 않고 믿을 수 있는 상태라는 뜻입니다.

웹 서비스는 수많은 사용자가 동시에 접속하여 데이터를 생성하고 수정합니다. 만약 데이터베이스가 엄격한 규칙 없이 아무 데이터나 받아들인다면, 시스템은 금방 엉망진창이 될 것입니다.

예를 들어, 쇼핑몰의 가격 정보에 문자열이 들어가거나, 존재하지 않는 회원이 물건을 구매하는 주문서가 생성된다면 서비스 운영 자체가 불가능해집니다. RDB는 이러한 일이 발생하지 않도록 시스템 차원에서 데이터를 보호합니다.

### 2. RDB가 데이터 무결성을 지키는 방법

관계형 데이터베이스는 크게 두 가지 강력한 장치를 통해 데이터 무결성을 보장합니다.

첫째, 스키마(Schema)를 통한 제약 조건입니다. RDB는 엑셀처럼 자유롭게 데이터를 입력하는 것이 불가능합니다. 테이블을 만들 때 미리 데이터의 구조를 정의해야 합니다. 나이 컬럼에는 숫자만, 이름 컬럼에는 문자만 들어오도록 강제합니다. 또한 NOT NULL 조건을 걸어 필수 입력값을 누락하지 않도록 막거나, UNIQUE 조건을 통해 중복된 ID 생성을 원천적으로 차단합니다. 즉, 형식에 맞지 않는 데이터는 아예 저장소에 들어올 수 없습니다.

둘째, 트랜잭션(Transaction)을 통한 처리입니다. 이것이 RDB를 사용하는 가장 강력한 이유입니다. 웹 서비스의 많은 기능은 단일 작업이 아닌 여러 단계의 작업으로 이루어집니다.

계좌 이체를 예로 들어보겠습니다.

1. A의 통장에서 100만 원을 뺀다.
2. B의 통장에 100만 원을 더한다.

이 두 과정은 반드시 하나의 묶음으로 성공해야 합니다. 만약 1번은 성공했는데 서버 오류로 2번이 실패한다면, 100만 원은 허공으로 사라집니다.

RDB의 트랜잭션 기능은 이 모든 과정이 완벽하게 성공(Commit)하거나, 하나라도 실패하면 작업 전 상태로 되돌리는(Rollback) 기능을 제공합니다. 이를 통해 데이터가 꼬이거나 모순되는 상황을 방지합니다.

### 마치며

결국 웹 서비스에서 RDB를 사용하는 이유는 데이터를 단순히 저장하기 위함이 아니라, 데이터를 안전하고 정확하게 지키기 위함입니다.

사용자의 자산, 개인정보, 주문 내역 등 서비스의 신뢰와 직결되는 중요한 데이터를 다룰 때, 데이터 무결성을 강력하게 보장해 주는 RDB는 선택이 아닌 필수입니다.
