안녕하세요.

백엔드 개발을 공부하다 보면 **"실시간 채팅을 구현해보자"** 혹은 **"주식 시세처럼 데이터가 계속 바뀌는 서비스는 어떻게 만들지?"**라는 고민에 빠지게 됩니다.

가장 먼저 떠오르는 기술은 단연 **WebSocket**입니다. 하지만 모든 실시간 서비스가 WebSocket으로만 만들어지는 것은 아닙니다. 상황에 따라 **WebRTC**가 필요할 수도 있고, **gRPC**가 더 효율적일 수도 있습니다.

오늘은 실시간 통신을 위한 대표적인 기술 3가지를 비교하고, 언제 무엇을 써야 하는지 정리해 보겠습니다.

---

### 1. 왜 HTTP만으로는 안 될까?

우리가 가장 많이 사용하는 **HTTP 프로토콜**은 기본적으로 **무상태(Stateless)**이자 **단방향** 통신입니다.

- 클라이언트가 요청(Request)을 보내야만,
- 서버가 응답(Response)을 줄 수 있습니다.

즉, 서버가 할 말이 있어도 클라이언트가 물어보지 않으면 데이터를 보낼 방법이 없습니다. 마치 편지를 보내놓고 답장이 올 때까지 하염없이 기다리는 것과 같습니다. 실시간성이 중요한 서비스에서는 치명적인 단점입니다.

---

### 2. WebSocket: "서버가 먼저 말을 걸어야 할 때"

WebSocket은 한 번 연결을 맺으면(Handshake), 끊을 때까지 **양방향**으로 데이터를 주고받을 수 있는 영구적인 연결을 유지합니다. HTTP와 달리, **서버가 원할 때 언제든 클라이언트에게 데이터를 보낼 수 있습니다.**

#### ✅ 언제 사용하나요? (Best Use Case)

1. **실시간 채팅/메신저:** 내가 메시지를 입력하지 않아도 상대방의 메시지가 즉시 내 화면에 떠야 할 때.
2. **실시간 데이터 시각화:** 주식 거래소(업비트, 빗썸), 스포츠 중계 스코어 보드 등 데이터가 0.1초 단위로 갱신될 때.
3. **협업 도구:** 구글 닥스(Google Docs), 피그마(Figma)처럼 여러 사람이 동시에 문서를 편집할 때.
4. **알림(Notification):** 사용자의 행동과 무관하게 "좋아요가 눌렸습니다", "배달이 시작되었습니다" 같은 알림을 보낼 때.

---

### 3. WebRTC: "서버 거치지 말고 우리끼리 직접(P2P)"

WebSocket이 [클라이언트 ↔ 서버] 통신이라면, **WebRTC(Web Real-Time Communication)**는 **[클라이언트 ↔ 클라이언트]** 직접 통신을 지향합니다.

#### ✅ 특징

- **P2P (Peer-to-Peer):** 서버를 거치지 않고 사용자끼리 직접 데이터를 주고받습니다. 서버 부하가 적고 전송 속도가 매우 빠릅니다.
- **UDP 기반:** 데이터의 정확성보다는 **속도**가 생명입니다. 영상이 살짝 깨지더라도 끊기지 않고 전송되는 것이 중요하기 때문입니다.

#### ✅ 언제 사용하나요?

- **화상 회의:** Zoom, Google Meet
- **음성 통화:** 보이스톡, 디스코드 음성 채팅
- **라이브 스트리밍:** 저지연(Low-latency) 방송

---

### 4. gRPC: "서버끼리 초고속으로 대화할 때"

구글에서 만든 **gRPC**는 주로 **[서버 ↔ 서버]**, 즉 마이크로서비스 아키텍처(MSA) 환경에서 서비스 간 통신에 사용됩니다.

#### ✅ 특징

- **Protocol Buffers (Protobuf):** 무거운 JSON(텍스트) 대신, 데이터를 이진(Binary) 형태로 압축해서 보냅니다. 크기가 훨씬 작아서 전송 속도가 빠르고 파싱 성능이 압도적입니다.
- **HTTP/2:** 한 번의 연결로 여러 요청을 동시에 처리할 수 있고, 양방향 스트리밍도 지원합니다.

#### ✅ 언제 사용하나요?

- **MSA 내부 통신:** "주문 서버"가 "결제 서버"에게 요청을 보낼 때, 0.01초라도 더 빨리 처리해야 하는 경우.
- **고성능이 필요한 백엔드:** 대용량 데이터를 처리하는 내부 시스템 간의 통신.

### 💡 요약

|  |  |  |  |
| --- | --- | --- | --- |
| **기술** | **통신 방식** | **주요 특징** | **추천 서비스** |
|  |  |  |  |
| --- | --- | --- | --- |
| **WebSocket** | Client ↔ Server | 양방향, 영구 연결, 안정적 | 채팅, 주식 시세, 알림 |
| **WebRTC** | Client ↔ Client (P2P) | 서버 미경유, UDP, 초저지연 | 화상 회의, 음성 통화 |
| **gRPC** | Server ↔ Server | 이진 데이터(Protobuf), 고성능 | MSA 내부 통신 |

### 마치며

"실시간 기능을 넣자!"라고 해서 무작정 WebSocket 라이브러리부터 설치하기보다, 내가 만들려는 서비스가 **텍스트 위주의 채팅**인지, **얼굴을 보고 대화하는 화상 회의**인지, 아니면 **서버 간의 빠른 통신**인지 먼저 파악하는 것이 중요합니다.
